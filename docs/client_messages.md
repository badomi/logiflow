## 회신 2 — 「메일 자동화 시스템 설계 및 개발 환경 관련 질의서」 공식 회신

안녕하세요 : )
보내주신 「메일 자동화 시스템 설계 및 개발 환경 관련 질의서」를 검토하여 아래와 같이 회신드립니다. 결론부터 말씀드리면 네 개 안건 모두 승인되었으며, 일부 안건에는 진행 시 유의사항을 함께 전달드립니다.

**1. 로컬 LLM + 룰 베이스 하이브리드 아키텍처 — 승인**
외부로 데이터가 전송되지 않는 로컬 LLM으로 추출(초안 파싱)을 수행하고, 정합성 검증·단가 계산은 룰 베이스로 처리하는 하이브리드 구조 도입을 승인합니다. 다만 추출 정밀도가 본 시스템 신뢰성의 핵심인 만큼, 로컬 LLM 도입 이후에도 NFR-01의 정밀도 목표 달성과 고도화에 각별히 신경 써 주시기 바랍니다.

**2. 파일럿 구동 및 DB 환경 — 승인 (자체 구축)**
개발팀에서 별도의 DB 환경을 구축하여 시스템을 개발·운영하는 방식으로 진행해 주시기 바랍니다. 다만 향후 사내 환경으로의 이관을 고려하여, 이관이 용이하도록 스키마 구조를 이식성 있게 설계해 주시기 바랍니다.

**3. 요구사항 변경 요청서 — 전체 승인**
첨부해 주신 변경 요청 3건을 모두 승인합니다.
- FR-101: 담당자가 Outlook 패널에서 직접 실행하는 방식
- FR-104: 담당자 확인을 거쳐 기존 Case와 병합하는 방식
- FR-202: 문자열 기반 유사도(편집거리 등) 우선 적용

해당 변경 사항은 요구사항 정의서에 반영하여 개정본(Rev 1.3)으로 공유드리겠습니다.

**4. 개발 착수 자료 및 권한 제공 — 금주 내 제공 예정**
개발 착수에 필요한 유형별 샘플 메일과 샘플 요율표·부대비용 Excel 양식은 금주 내 제공 예정입니다. 준비되는 대로 순차적으로 전달드리겠습니다.

## 팀 해석 메모
- 샘플 메일·견적서 양식은 이후 Notion 페이지("해운 물류 업무 이메일 샘플 모음(교육용)")로 전달됨 → `docs/samples.md`. 발주 측에서 받을 자료는 이것으로 전부로 판단.
- "Outlook 설정을 위한 서버 및 설정값" 질문은 아직 우리가 답하지 않음. 개인 계정 개발 단계에서는 회사에서 받을 것 없음. 사내 배포 시 필요한 것(관리자 애드인 중앙 배포, Graph용 앱 등록·권한 동의)은 추후 정리해 회신.
- 원래 변경 요청서의 3건은 FR-101·104·306이었으나 회신에는 306 대신 202가 기재됨. Rev 1.3 수령 시 FR-306(무응답 독촉 수동 방식) 반영 여부 확인. C등급이라 급하지 않음.
