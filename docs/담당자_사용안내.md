# LEONA 자동견적 — 담당자 사용 안내

견적 요청 메일을 Outlook에서 열고 LEONA 패널 버튼만 누르면, 항목을 뽑아 빠진 정보를 묻거나 견적서를 만들어 줍니다.
**메일은 자동으로 나가지 않습니다.** 보내기는 항상 담당자가 직접 누릅니다.

---

## 1. 한 건 처리 흐름

```
견적 요청 메일 열기 → LEONA 패널 [케이스 생성]
   ├ 상태 '정보부족' → [보완 요청 초안] → 회신 창에서 [앱] → LEONA → 확인 후 보내기
   │                    화주 회신이 오면 → 회신 메일에서 LEONA → [병합] → 다시 자동 판정
   ├ 상태 '계산완료' → [견적서 송부 초안] → 견적서가 붙은 회신 창 → 확인 후 보내기
   └ 상태 '보류'    → 패널의 '보류 사유'를 보고 직접 처리 (아래 3번)
```

| 단계 | 누르는 곳 | 결과 |
|---|---|---|
| 1 | 견적 요청 메일 → [앱] → **LEONA** → **[케이스 생성]** | 케이스 번호(LQ-YYYY-MMDD-NNN) 발급, 항목 자동 추출 (수십 초 걸릴 수 있음) |
| 2 | 패널 '항목 추출' 확인 | 뽑힌 값 목록. **(확인 필요)** 표시는 자신 없는 값이라 저장하지 않은 것. 값에 마우스를 올리면 근거 문장 |
| 3a | 정보부족 → **[보완 요청 초안]** | '보완 요청 문항' 칸에 빠진 항목이 자동으로 채워져 있음. 고쳐도 됨. 회신 창이 열리면 **그 창에서 [앱] → LEONA**를 열어야 제목에 케이스 번호가 들어가고 초안함에 저장됨 |
| 3b | 계산완료 → **[견적서 송부 초안]** | 견적서(XLSX, LibreOffice가 있으면 PDF도)가 **붙은 회신 창**이 열림. 첨부를 열어 금액 확인 후 보내기 |
| 4 | 화주 회신 메일 → LEONA → **[병합]** | 회신 내용을 합쳐 다시 추출·판정. 화주가 **번호에 맞춰 값만** 적어도(`1. 2026-10-20`) 알아본다. 모자란 게 남아 있으면 다시 3a |
| 5 | 보낸 메일 → LEONA → [발송 기록] | 발송 시각·담당자 기록, 상태 '발송완료' |

## 2. 상태 뜻

| 상태 | 뜻 | 할 일 |
|---|---|---|
| 수신·파싱중·재파싱 | 추출 중 | 잠시 기다림 (패널이 자동 갱신) |
| 정보부족 | 견적에 필요한 값이 빠짐 | 보완 요청 |
| 보완대기 | 보완 요청을 보냄 | 화주 회신 기다림 → 오면 [병합] |
| 계산완료 | 견적서 생성됨 | 견적서 송부 |
| 보류 | 자동으로 처리하면 안 되는 건 | 사유 확인 후 직접 처리 |
| 실패 | 처리 중 오류 (케이스·원문은 보존) | [다시 추출], 계속되면 관리자에게 |

## 3. 보류 사유별 처리

| 보류 사유 | 뜻 | 처리 |
|---|---|---|
| 다품목 — 수동 처리 대상 | 품목이 둘 이상 (자동 견적 범위 밖, 정의서 FR-210) | 직접 견적 |
| 위험물 가능성 키워드 | 배터리·스프레이·화학 등 | MSDS 확인 후 직접 견적 |
| 요율 미등록 구간 | 그 구간 요율이 DB에 없음 | 관리자에게 요율 등록 요청 (4-1) |
| 해상운임 요율 없음 | CIF인데 그 도착항 운임이 없음 | 선사 운임 확인 후 요율 등록 |
| 국내 부대비용(THC 등) 요율 없음 | 그 컨테이너 규격의 THC 등이 없음 | 부대비용 요율 등록 |

## 4. 자주 겪는 문제

| 증상 | 원인 | 해결 |
|---|---|---|
| "항목 추출이 꺼져 있어 실행만 기록했습니다" | 추출 설정이 꺼짐 | 관리자: 4-2 설정 점검 → `.env`에 `EXTRACTION_MODE=hybrid` → 서버 재시작 → 패널 **[다시 추출]** |
| 설정을 고쳤는데 그대로 | 예전에 만든 케이스를 보고 있음 | 그 케이스에서 **[다시 추출]** (같은 메일로 [케이스 생성]은 기존 케이스를 돌려줌) |
| "LLM: 사용 못 함 — 키워드 규칙 결과만" | 로컬 LLM이 45초 안에 답을 못 줌 | 결과는 정상(규칙 기반). 자주 나면 관리자가 더 작은 모델로 (4-3) |
| 견적서 파일명만 본문에 있고 첨부 없음 | 예전 방식 창 | 패널을 새로고침(Ctrl+F5) 후 [견적서 송부 초안] 다시. 그래도 없으면 그 창에서 [앱] → LEONA |
| 값이 틀리게 뽑힘 | 메일 표현이 특이함 | 필드 수정: 지금은 `http://localhost:8000/docs` → `POST /api/cases/{케이스번호}/fields/{필드}` (패널·콘솔 화면은 D트랙 예정). 수정 이력이 남고 다시 추출해도 유지. 그 메일은 관리자에게 공유 (추출 개선 자료) |
| 금액이 이상함 | 요율표가 오래됐거나 대수 산정 | 견적서 비고의 '컨테이너 대수 산정' 줄 확인, 관리자에게 요율 확인 요청 |

# 관리자용

## 4-1. 요율 올리기 (매달 운임표가 바뀔 때)

1. 지금 요율 내려받기: 브라우저에서 `http://localhost:8000/api/rates/export` (또는 `server` 폴더에서 `.venv\Scripts\python -m app.rates export 현재_요율.xlsx`)
2. '요율' 시트를 고치거나, 새 운임표를 같은 칸에 붙여 넣는다. **'출처'를 같게 쓰면 그 출처 요율만 통째로 바뀐다** (예: `2026-11 D선사 월간운임`).
   작성법은 '작성 안내' 시트. 빈 양식: `http://localhost:8000/api/rates/template`
3. 올리기: `http://localhost:8000/docs` → `POST /api/rates/import` → 파일 선택 → Execute
   (또는 `.venv\Scripts\python -m app.rates import 요율.xlsx`)
4. **틀린 줄이 하나라도 있으면 아무것도 바뀌지 않고** 몇 행이 왜 틀렸는지 나온다 (예: `요율 3행 도착항: 항구를 찾을 수 없습니다 (SIDNEY) — 혹시 AUSYD?`)
5. 적용 기간이 끝난 요율은 설정 점검(4-2)에 경고로 나온다.

규칙: 해상운임은 구분코드 `OCEAN_FREIGHT`·인코텀즈 `CIF`, 출발지 터미널 비용은 `THC`로 써야 견적 로직이 알아본다.

## 4-2. 설정 점검

`server` 폴더에서 `.venv\Scripts\python -m app.diagnostics` (서버가 꺼져 있어도 됨), 또는 `http://localhost:8000/api/health/detail`.
`.env` 파일, 추출 모드, LLM 연결·모델 설치, 요율 개수·만료, PDF 도구를 확인하고 **할 일을 한국어로** 알려준다.

## 4-3. 설정 파일 `server\.env`

| 항목 | 값 | 설명 |
|---|---|---|
| `EXTRACTION_MODE` | `hybrid` / `rules` / `off` | hybrid = 규칙 + 로컬 LLM, rules = 규칙만 |
| `LLM_MODEL` | `qwen3:1.7b` 등 | `ollama list`에 나오는 이름 그대로. 내장그래픽 노트북은 1.7b~4b |
| `LLM_SCOPE` | `all` / `missing` | all = LLM이 모든 항목을 읽음 (유연, 기본) · missing = 규칙이 못 찾은 빈 칸만 (느린 PC) |
| `LLM_TIMEOUT_S` | `45` | 이보다 늦으면 규칙 결과로 진행 (메일 1건 60초 기준). 자주 넘으면 `LLM_SCOPE=missing` 또는 더 작은 모델 |
| `QUOTE_PDF` | `true` | LibreOffice가 있으면 PDF도 생성 |

`.env`를 고친 뒤에는 **서버를 껐다 켜야** 적용된다 (`start-dev.bat` 다시 실행). 메모장으로 만들 때 `.env.txt`가 되지 않게 주의.

## 4-4. 놓친 표현 모아 보기

`server` 폴더에서 `.venv\Scripts\python -m app.extraction.report` (또는 `http://localhost:8000/api/extraction/review-report`).
최근 30일 동안 **값을 찾았지만 읽지 못한 원문**을 항목별로 보여 준다 (예: `[grossWeightKg] 3건 — 예상 총중량: 오백 킬로`).
자주 나오는 표현은 아래 4-5의 사전에 추가하면 다음부터 자동으로 읽는다. 한 달에 한 번 정도 확인 권장.

## 4-5. 규칙·사전 고치기 (코드 수정 없음)

| 파일 | 내용 |
|---|---|
| `server/app/data/validation_rules.json` | 필수 항목, 위험물 키워드, 부피 허용 오차, **화주에게 보내는 질문 문구** |
| `server/app/extraction/data/fields.json` | 메일 라벨 사전(국·영문), 필드별 신뢰도 임계치 |
| `server/app/extraction/data/ports.json` | 항구명 → UN/LOCODE |

고친 뒤 `server` 폴더에서 `.venv\Scripts\python -m pytest -q`로 깨진 곳이 없는지 확인하고 서버를 재시작한다.
사전을 고쳤다면 `.venv\Scripts\python -m eval.run_eval`로 추출 정밀도가 떨어지지 않았는지도 본다.
